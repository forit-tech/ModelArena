# ModelArena — границы сервиса

Документ фиксирует, **чем ModelArena является и чем не является**, чтобы граница с DataArena
не размылась. Написан на этапе аудита, до начала реализации.

Полный аудит исходного проекта: [DataArena/AUDIT.md](../../DataArena/AUDIT.md).

---

## 1. Место в связке

```
DataArena                                     ModelArena
файлы → workspace → профиль → правки →
преобразования → сборка → экспорт
                         ↓
                 Dataset Package  ──────────→  чтение package
                                               выбор target и задачи
                                               стратегия валидации
                                               обучение кандидатов
                                               сравнение метрик
                                               разбор ошибок
                                               инспекция утечек
                                               предсказание на новых данных
                                               артефакты модели
```

DataArena заканчивается на готовом датасете. ModelArena начинается с него.

**ModelArena не читает сырые файлы пользователя, не редактирует данные, не строит join
и не занимается очисткой.** Если данные оказались плохими — пользователь возвращается
в DataArena, а не чинит их здесь.

---

## 2. Что переносится из AutoDataAnalysis

ML-слой существующего проекта работает, покрыт тестами и проходит все quality gates
(148 backend-тестов зелёные, ruff и mypy чистые — проверено запуском). Он переносится
**без изменения логики**.

| Модуль | LOC | Что делает |
|---|---|---|
| `ml/training/` | 1 028 | Обучение 4 кандидатов на задачу, всегда обучаемый baseline, препроцессинг единым `Pipeline` |
| `ml/validation/leakage.py` | 487 | Инспектор утечек |
| `ml/validation/splits.py` | 460 | random / stratified / temporal / group + автовыбор стратегии |
| `ml/evaluation/` | 879 | Метрики, bootstrap-интервалы, error analysis, verdict |
| `ml/inference/predictor.py` | 438 | Предсказание с валидацией схемы и проверкой новизны строк |
| `ml/explainability/importance.py` | 318 | Permutation importance |
| `ml/experiments/` | 342 | Хранилище экспериментов: `Protocol` + файловая реализация, `joblib` |
| `api/routes/{training,experiments,inference}.py` | 221 | HTTP-слой |
| `schemas/ml.py` | 226 | Схемы API |
| frontend `features/{models,evaluate,test-drive}`, `LeakagePanel`, `types/ml.ts` | 2 495 | Интерфейс |

Единственная правка при переносе: **вход берётся из Dataset Package, а не из `UploadFile`**.
Это новый адаптер; ML-код не трогается.

Из общей инфраструктуры переносится то же, что и в DataArena: контракт ошибок,
транспортный слой frontend, `ErrorBoundary`, дизайн-токены.

## 3. Что ModelArena добавляет сверх текущего состояния

Из требований пользователя к ModelArena, которых в AutoDataAnalysis нет:

- **подбор лучшей модели под датасет** — сейчас обучаются 4 фиксированных кандидата;
  нужен осмысленный отбор с обоснованием выбора, а не таблица метрик;
- **прогноз деградации** — оценка того, как модель поведёт себя на смещённых данных;
- **суждение о наполненности датасета** — достаточно ли данных для выбранной модели,
  кривые обучения;
- **диагностика переобучения** — разрыв train/holdout, поведение по фолдам;
- **артефакты и их применение** — что именно сохранять, как загрузить, как использовать
  в чужом коде; сейчас `joblib`-артефакт есть, инструкции по применению нет;
- кросс-валидация (сейчас один holdout + bootstrap-интервал).

Всё перечисленное — предмет отдельного планирования после того, как перенос состоится.

## 4. Правило границы

Функция принадлежит **DataArena**, если для её вычисления не нужен target.
Функция принадлежит **ModelArena**, если нужен.

Проверка на краевых случаях:

| Функция | Где | Почему |
|---|---|---|
| Корреляционная матрица | DataArena | target не нужен |
| Кардинальность, дисбаланс колонки | DataArena | считается по одной колонке |
| Кандидаты в target с объяснением | DataArena → `hints` в package | это подсказка, не решение |
| Class balance выбранного target | ModelArena | target уже выбран пользователем |
| Feature importance | ModelArena | требует обученной модели |
| Target leakage | ModelArena | без target утверждение необоснованно |
| Train/test split | ModelArena | зависит от задачи и стратегии валидации |
| Scaling, encoding под модель | ModelArena | часть ML-пайплайна |
| Дедупликация, заполнение пропусков | DataArena | свойство данных, не модели |

При сомнении функция уходит в ModelArena: обратный перенос дешевле распутывания.

## 5. Контракт

Единственная точка соприкосновения — [Dataset Package `dataarena.package/1`](../../DataArena/docs/contracts/dataset-package-v1.md).

Обязательства ModelArena:

1. **не импортирует Python-модули DataArena** — только чтение package;
2. читает `manifest.json`, проверяет `format` и мажорную версию;
3. при неизвестной мажорной версии — отказ с понятным сообщением, а не попытка угадать;
4. незнакомые поля игнорирует;
5. проверяет `sha256` частей перед использованием;
6. `hints.suggested_targets` показывает пользователю как подсказку — **target выбирает человек**;
7. `profile.computed_on.sampled: true` означает, что статистики приблизительны, и это
   должно быть видно в интерфейсе.

В репозитории лежит тот же **golden package**, что и в DataArena. Он — источник истины
для обеих сторон.

## 6. Порядок работ

| Этап | Содержание |
|---|---|
| 0 | Границы и контракт — этот документ |
| 1 | Скелет репозитория, CI, перенос core и транспортного слоя |
| 2 | Адаптер чтения Dataset Package + golden package тест |
| 3 | Перенос ML-слоя целиком, вместе с тестами |
| 4 | Перенос frontend-разделов Model / Evaluate / Test Drive |
| 5 | Кросс-валидация и осмысленный отбор модели |
| 6 | Диагностика: переобучение, наполненность датасета, кривые обучения |
| 7 | Прогноз деградации |
| 8 | Артефакты: что сохранять, как загружать, как применять |

Этапы 1–4 — перенос работающего кода. Этапы 5–8 — новая функциональность,
и планировать их следует отдельно, когда перенос завершён.

---

## 7. Независимость

ModelArena запускается без DataArena: package можно передать файлом.
DataArena запускается без ModelArena: кнопка «Open in ModelArena» показывает, что сервис
недоступен, и на этом всё.

Обе стороны покрываются тестом на работу в одиночку.
