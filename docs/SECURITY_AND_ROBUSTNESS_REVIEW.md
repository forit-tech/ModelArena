# Adversarial review этапа 1

Ревизия собственного кода на предмет не обычных багов, а мест, где код **формально
существует, но не делает обещанного** или скрывает ошибку.

Дата: 2026-09-07. Объём: `backend/` (профиль, реестр, чтение пакета, HTTP-слой),
`frontend/src/api` (транспорт). Зеркало контракта не ревизуется: оно побайтово
принадлежит владельцу (D-17).

**Метод.** Каждая находка сначала воспроизведена запуском, потом исправлена, потом
закрыта регрессионным тестом. Для двух самых серьёзных дополнительно проведена мутация:
защита снималась обратно, и проверялось, что краснеют именно нужные тесты.

## Мутационная кампания

Десять защит сняты по одной, каждая — отдельным прогоном всего набора:

```
канонизация меток                    покраснели
обучение при скользящем окне         покраснели
отпечаток покрывает обучение         покраснели
неизвестное время как прошлое        покраснели
обнаружение копии цели               покраснели
пересечение групп                    ЗЕЛЁНЫЕ -> найдена L-07, тест переписан
пересечение дублей                   покраснели
пропуск кодирует цель                покраснели
связь утечки с готовностью           покраснели
сообщение о невыполненной проверке   покраснели
```

После правки L-07 — все десять мутаций пойманы.

## Инварианты разбиения

Проверены для random, stratified, group и rolling window:

- `train ∩ validation = ∅` в каждом фолде;
- holdout не пересекается с обучающим пулом;
- при скользящем окне обучение содержит **только прошлое** — это отдельный тест,
  потому что нарушение здесь даёт красивые метрики на будущем и выглядит как успех;
- при групповом протоколе сущность целиком по одну сторону границы.

| C повторяющийся клиент, случайное разбиение | `none` | `HIGH_RISK` | — |
| D тот же датасет, групповой протокол | `none` | `READY` | — |
| E временная колонка, скользящее окно | `none` | `CAUTION` | — |
| F булева цель | — | — | положительный класс `'True'`, классы `['False', 'True']` |
| G регрессия, почти-копия цели | `confirmed` | `BLOCKED` | `target_derived_feature`, `single_feature_reconstructs_target` |
| H сильный честный предиктор | `none` | `HIGH_RISK` | — |

Три результата стоит прочитать внимательно.

**C и D — одна и та же пара данных.** Со случайным разбиением готовность падает
до `HIGH_RISK` (структура в данных есть, протокол её игнорирует), с групповым —
поднимается до `READY`. Утечка при этом в обоих случаях `none`, и это правильное
разделение ролей: Guard проверяет **фактические границы** для объявленной колонки
группировки, а Readiness отвечает за структуру, которую пользователь не учёл.

**H не помечен утечкой.** Сильный честный предиктор даёт `none` — ради этого
и существует отрицательный набор фикстур. `HIGH_RISK` в готовности вызван другими
причинами и утечкой не является.

**F подтверждает канонизацию меток.** Положительный класс `'True'`, а не `'true'`:
представление согласовано между постановкой задачи и проверками.

## Мутационная кампания

Тринадцать защит снимались по одной. Каждая мутация обязана делать конкретный тест красным
(D-20). Пропущенных нет.

| Мутация | Поймана тестом |
|---|---|
| препроцессинг обучается на всём датасете, а не на обучающей части фолда | `test_fitting_on_validation_rows_would_be_visible` |
| движок строит собственное разбиение вместо `FoldPlan` | `test_arena_never_builds_its_own_splits` |
| baseline можно убрать выбором пользователя | `test_baseline_cannot_be_deselected` |
| адаптер запрашивает все ядра вместо бюджета | `test_no_adapter_or_engine_asks_for_every_core` |
| прогон с упавшим участником объявляется успешным | `test_partial_is_not_success` |
| отказ одного участника останавливает весь прогон | `test_failed_contender_does_not_destroy_finished_results` |
| остановка меняет только состояние, но не завершает обучение | `test_cancel_stops_training_and_keeps_finished_results` |
| публикация переносит метаданные без предсказаний | `test_clean_run_succeeds_and_leaves_verifiable_predictions` |
| столбцы вероятностей берутся в порядке модели, а не задачи | `test_probabilities_follow_the_canonical_label_order` |
| защита от двойного запуска отключена | `test_repeated_submission_does_not_create_a_second_run` |
| удвоенное out-of-fold предсказание не проверяется | `test_duplicated_out_of_fold_prediction_is_refused` |
| прогон, переживший перезапуск, остаётся `RUNNING` навсегда | `test_restart_turns_a_stuck_running_into_a_terminal_state` |
| результаты не переживают перезапуск backend | `test_history_and_results_survive_a_new_runner` |

Первая мутация заслуживает пояснения, потому что структурная проверка её **не ловит**.
Обучение на всех строках оставляет и покрытие полным, и форму предсказаний верной — меняются
только числа, а на отделимых данных они не меняются вовсе. Ловит её поведенческий тест:
на данных **без всякой связи** признаков с целью ближайший сосед при `k = 1` отвечает
случайно, если обучен только на обучающей части, и попадает всегда, если обучающая часть
включает проверяемую строку. Разрыв между случайным угадыванием и единицей ни с чем
не спутать.

## Принятые риски

**Осиротевший процесс обучения после аварийного убийства backend.** Если backend снять
принудительно, его дочерние процессы на Windows не умирают вместе с ним и досчитают своё,
занимая процессор. Порчи состояния при этом произойти не может: восстановление стирает
каталог `.staging` прогона, поэтому опубликовать результат такому процессу некуда, а сам
прогон уже переведён в `INTERRUPTED`. Цена — потраченное процессорное время до естественного
конца работы, величина ограничена самой задачей. Автоматическое добивание сирот потребовало
бы хранить и сверять идентификаторы процессов между запусками; отложено.

**Прогресс внутри одного фолда не показывается.** Модель не отдаёт его, а выдумывать нельзя
(D-28). Долгий фолд выглядит как пауза между событиями — это честно, но неприятно.
Смягчается предельным временем на контендера.

**`predict_proba` считается отдельным проходом по проверочной части.** Для дорогих моделей
это заметная добавка. Осознанный размен: вероятности нужны для ранговых метрик и калибровки,
а хранить их первичным артефактом важнее скорости (D-6).

**Опрос вместо потока событий.** Раз в секунду; состояние на сервере меняется по фактам.
Задержка до секунды на достоверность не влияет, а поток событий добавил бы переподключения,
не добавив правды.
