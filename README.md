# ModelArena

**Лаборатория честного сравнения ML-моделей на подготовленном датасете.**

Проект FORIT TECH.

---

> ## Состояние: кандидат на первый локальный релиз
>
> Путь проходится целиком: пакет или файл → выбор цели → готовность и утечки →
> протокол → обучение нескольких моделей → честное сравнение и чемпион → диагностика →
> разбор ошибок → влияние признаков → история экспериментов → сохранённая модель →
> применение к новым данным → выгрузка предсказаний.
>
> Это **локальный** инструмент, а не production-сервис: ни аутентификации,
> ни многопользовательского режима, ни развёртывания в кластере здесь нет и не обещается.
>
> 310 backend-тестов, 31 frontend-тест.

---

## Вопрос, на который отвечает ModelArena

> У меня есть подготовленный датасет и ML-задача. Какая модель подходит для неё лучше,
> насколько я могу доверять сравнению и **почему**.

Это не кнопка «сделать AutoML». Каждое решение системы объясняется числами и может быть
переопределено. Там, где вывод сделать нельзя, ModelArena пишет «недостаточно данных»,
а не показывает красивое неверное число.

Правила, которым подчинён весь код:

- **пустого места не бывает.** Недоступная библиотека, неуместная модель и отказ обучения
  показываются со статусом и причиной. Исчезнувший из списка участник читался бы как
  проигравший, хотя его не запускали;
- **«не удалось посчитать» — отдельное состояние, а не ноль.** ROC-AUC на части с одним
  классом не равен нулю: он не определён, и подставленный ноль испортил бы среднее;
- **честность сравнения задаётся протоколом.** Одни фолды, один seed, один набор признаков
  и один модуль метрик на всех. Способ подготовки признаков при этом может различаться
  по семействам моделей: гнать бустинг через `StandardScaler` — не «честно», а искусственно
  ухудшать одного участника;
- **«первый в таблице» и «победитель» — разные утверждения.** Если разница между моделями
  меньше её собственного колебания по фолдам, они называются неразличимыми, а порядок
  между ними определяется объявленным заранее правилом;
- **вывода без измерения не бывает.** Слово «переобучение» появляется только рядом
  с измеренным разрывом и порогом, при котором оно сказано.

## Границы

ModelArena начинается там, где заканчивается [DataArena](https://github.com/forit-tech/DataArena):
датасет уже собран, почищен и выгружен.

**ModelArena не читает сырые файлы, не редактирует данные и не строит join.**
Правило разделения: не нужен target — это DataArena; нужен target, модель, протокол
или метрика — это ModelArena. Масштабирование и кодирование под конкретный estimator —
ModelArena; заполнение пропусков как правка самих данных — DataArena.

Единственная точка соприкосновения — контракт Dataset Package v1. Он заморожен и проверен
независимой реализацией потребителя: 14 фикстур из 14 (отчёт —
[docs/contracts/CONSUMER_VERIFICATION.md](docs/contracts/CONSUMER_VERIFICATION.md)).
Зеркало контракта в `contracts/dataset-package/v1/` побайтово совпадает с оригиналом
у владельца. Прямых импортов кода DataArena нет.

Работать друг без друга обе стороны умеют: пакет можно передать файлом.

## Установка и запуск

```bash
pip install -e ".[dev]"
python -m uvicorn backend.api.app:app --host 127.0.0.1 --port 8520
```

```bash
npm install --prefix frontend
npm run dev --prefix frontend
```

Интерфейс — `http://127.0.0.1:5173`, документация API — `http://127.0.0.1:8520/docs`.
Ни одной переменной окружения не требуется: у всех настроек есть рабочие значения.
Каталог артефактов задаётся через `MARENA_ARTIFACTS_DIR`, по умолчанию — `./artifacts`.

Бустеры опциональны — ядро работает на одних зависимостях scikit-learn:

```bash
pip install -e ".[boosters]"
```

Без них XGBoost, LightGBM и CatBoost **остаются в списке участников** со статусом
«не установлен» и текстом, что поставить.

## Поддерживаемые задачи и модели

| Задача | Метрики | Протоколы |
|---|---|---|
| Бинарная классификация | ROC-AUC, PR-AUC, F1, precision, recall, accuracy, balanced accuracy, log loss, Brier | стратифицированные фолды, фолды по сущностям, скользящее окно по времени |
| Многоклассовая классификация | macro F1, accuracy, balanced accuracy, log loss | то же |
| Регрессия | RMSE, MAE, R², MAPE (где определён) | обычные фолды, по сущностям, скользящее окно |

Набор моделей намеренно небольшой и рабочий, а не «зоопарк»: обязательный baseline
(самый частый класс / медиана), логистическая регрессия и Ridge, Random Forest,
Extra Trees, HistGradientBoosting, SVM, KNN, плюс опциональные XGBoost, LightGBM, CatBoost.

Каждый участник подчиняется общему протоколу, а не своему. Модель, неуместная на этих
данных, показывает ограничение честно: SVM отказывается от десятков тысяч строк
(время растёт как квадрат), KNN — от сотен тысяч (расстояние до каждого объекта
на каждое предсказание).

## Пользовательский путь

| Шаг | Что происходит |
|---|---|
| Импорт | Dataset Package или файл. Снимок неизменяем, идентичность — логический отпечаток `dataarena-logical-sha256-v1`, поэтому один датасет из двух источников опознаётся как один |
| Постановка задачи | тип задачи по данным, предложение признаков и исключений — каждое с причиной и источником |
| Готовность | `READY / CAUTION / HIGH_RISK / BLOCKED` с объяснением каждой находки. Без искусственного балла 0–100 |
| Утечки | механизмы, а не корреляции: три уровня доказательности, «не удалось проверить» — отдельное состояние |
| Протокол | выбор стратегии разбиения с объяснением; фолды строятся сразу, а не обещаются |
| Прогон | обучение каждого участника в отдельном процессе, событийный прогресс, настоящая остановка |
| Сравнение | порядок по объявленной цели с объяснением, почему модель выше соседа |
| Чемпион | вердикт, а не argmax: победитель обязан устойчиво превзойти точку отсчёта |
| Диагностика | разрыв train-vs-validation, устойчивость по фолдам, разбор по классам либо остатки |
| Ошибки | конкретные строки с исходными значениями признаков |
| Влияние признаков | перестановочная важность на holdout, без причинных утверждений |
| Эксперименты | история прогонов и сравнение, начинающееся с различий в условиях |
| Модель | сохранённый артефакт: конвейер, схема признаков, метаданные, контрольная сумма |
| Применение | одна строка или файл, проверка схемы, выгрузка предсказаний |

## Диагностика

Разрыв между обучающей и проверочной частью **измеряется**, а не предполагается: прогон
сохраняет предсказания на подвыборке обучающей части каждого фолда, снятые тем же
конвейером. Эти строки модель видела при обучении, поэтому результат по ним завышен
по построению — и именно поэтому годится как верхняя опора разрыва. В ранжировании
они не участвуют никогда.

Пороги, при которых слой делает выводы, собраны в `backend/diagnostics/thresholds.py`,
объяснены и **отдаются наружу вместе с находкой**: порог, спрятанный в интерфейсе,
невозможно ни обсудить, ни воспроизвести.

Классификация и регрессия не притворяются одним случаем. Для классификации — матрица
ошибок, precision/recall/F1/поддержка по классам, разрез по уверенности. Для регрессии —
распределение остатков, систематическое смещение, ошибка по диапазонам цели, крупнейшие
промахи. Относительная ошибка считается только там, где знаменатель содержателен.

Кривая обучения переобучает модель на растущих долях той же обучающей части. Допустимые
выводы: качество растёт, вышло на полку, разброс перекрывает прирост, точек мало.
Обещаний вида «добавьте N строк и получите +X%» она не делает.

## Артефакты моделей

Артефакт — не голый `pickle`, а конвейер вместе со всем, без чего он бесполезен: схема
признаков с порядком колонок, постановка задачи и порядок классов, отпечаток снимка
данных, идентификаторы прогона и протокола, версии библиотек, контрольная сумма.

Загрузка сначала проверяет формат, мажорную версию и контрольную сумму — и только потом
читает файл. Расхождение версий библиотек показывается предупреждением, потому что
scikit-learn не гарантирует совместимости сериализации между версиями.

## Применение к новым данным

На данных для предсказания **ничего не обучается заново**: ни импьютер, ни кодировщик,
ни масштабирование. Пересчитанная на новых строках медиана дала бы другое числовое
представление тех же значений — и предсказание перестало бы соответствовать модели,
оставшись при этом правдоподобным. Это закреплено регрессионным тестом, который падает
при любом вызове обучения на пути предсказания.

Схема проверяется до предсказания: недостающая колонка — отказ, лишняя — предупреждение.
Порядок колонок во входном файле произволен и восстанавливается по манифесту.

## Граница доверия

`joblib` при загрузке артефакта **исполняет код**. Поэтому:

- загружаются только артефакты, созданные этим же приложением и лежащие внутри его
  каталога прогонов, и только после сверки контрольной суммы;
- загрузка произвольного файла с диска или из сети **не поддерживается** — обещание
  «безопасно загрузим любую модель» форматом не обеспечено;
- Dataset Package проверяется до чтения: путь каждой части сверяется с корнем архива,
  действует предел на размер данных и запрет вложенных архивов, а неизвестная мажорная
  версия отвергается, а не угадывается.

## Известные ограничения

- **Локальный инструмент.** Нет аутентификации, разграничения доступа и многопользовательского
  режима. Запускать на общедоступном адресе нельзя.
- **Кривая обучения считается синхронно** и ограничена сорока обучениями. Остановить
  её отдельно нельзя; предел и стоимость сообщаются заранее.
- **Подбор гиперпараметров не реализован.** Модели обучаются на объявленных настройках.
- **Сравнения с будущим датасетом (drift) нет.** Основание для него — сохранённый артефакт
  с отпечатком данных — уже есть, сам слой отложен.
- **Аварийно убитый backend оставляет дочерние процессы обучения** досчитывать своё.
  Порчи состояния не происходит: восстановление стирает staging, а прогон переводится
  в `INTERRUPTED`.
- **Настоящий producer пакетов DataArena ещё не подключён**; проверка контракта идёт
  на замороженном golden package.
- **Типы фронтенда написаны руками**, а не сгенерированы из OpenAPI.
- **`npm audit` показывает две moderate-находки в `vitest`** — это исполнитель тестов,
  в поставку он не входит (`npm audit --omit=dev` чист). Исправление доступно только
  в мажорной версии 5, и обновлять испытательный инструмент в день релиза рискованнее,
  чем отложить: уязвимость касается чтения файлов через подмену модулей в тестах,
  то есть кода, который мы пишем сами.
